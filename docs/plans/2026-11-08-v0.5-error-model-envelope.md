# v0.5.0-preview.1 — Error model & Envelope — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Koto 0.5.0-preview.1: abstract `Error` catalog, `ErrorList`/`FirstError`, `EnrichedError` + `AppResult<T>` in Application, `Envelope<T>` wire format replacing ProblemDetails, coarse status classifier, validation-pipeline fixes, handler fail-fast, no silent domain-event loss.

**Architecture:** Domain returns `Result<T>` (errors `Error`); handlers return `AppResult<T>` (errors `EnrichedError`); API serializes `Envelope<T>`. No implicit conversion Result→AppResult; three explicit verbs (`ForField`, `Enrich()`, `Enrich(map)`). Envelope DTO lives in Koto.Application so HTTP, SignalR and the HTTP client share it.

**Tech Stack:** .NET 10, C# 14 records, System.Text.Json (inbox), FastEndpoints 5.35, FluentValidation 12, xUnit + AwesomeAssertions.

**Spec:** `docs/packages/16-error-model-envelope.md`; decisions: `adr/ADR-026-error-model-and-envelope.md`.

## Global Constraints

- `TreatWarningsAsErrors=true`; CA2007 (`ConfigureAwait(false)`) is an error in `src/`.
- New public XML docs and READMEs in **English**; ADR/PLAN/spec in Russian.
- No new PackageReferences. `Koto.Domain` has zero dependencies.
- Error code format: `^[a-z0-9]+(?:-[a-z0-9]+)*(?:\.[a-z0-9]+(?:-[a-z0-9]+)*){2,}$` (≥3 kebab-case segments).
- Version string `0.5.0-preview.1` in `src/Directory.Build.props`; CI packs from tag `v0.5.0-preview.1`.
- Work on branch `feat/v0.5-error-model-envelope`; one commit per task; trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- Run the full suite with `dotnet test Koto.slnx --nologo` before the release task (Docker required for EFCore/Marten/Postgres tests).

## Review Focus

1. A derived error record whose property is itself an `Error` (e.g. `MeetupFullWithAlternative(MeetupFull Cause, …)`): details must flatten `Cause`'s properties, never serialize the nested object → pinned by `ErrorDetailsTests.Flattens_nested_error_properties` (Task 4).
2. `new EnrichedError(alreadyEnriched)`: must not double-wrap; keeps `Field`/`Details` of the inner → `EnrichedErrorTests.Wrapping_enriched_error_collapses_to_single_layer` (Task 4).
3. A handler that returns a failure with mixed `Field` and non-field errors: status is taken from the **first** error → `KotoApiOptionsTests.Status_for_list_is_status_of_first_error` (Task 9).
4. Envelope for `AppResult<Unit>` must serialize `result: null`, not `{}` → `EnvelopeTests.Unit_result_serializes_as_null` (Task 5).
5. `AddKotoApplication` with a command whose handler lives in an assembly not scanned must still start when `ValidateHandlers = false` → `HandlerValidationTests.Validation_can_be_disabled` (Task 7).
